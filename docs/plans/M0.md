# M0 — Foundations

**Goal (PRD):** monorepo with `backend/`, `app/`, `admin/`, `infra/`; CI for lint + tests; design
tokens from the canvas.
**Accept:** `docker compose up` brings up every service, `GET /api/v1/health` returns 200, and
the app shows the Welcome screen with the real fonts and colours.

## 1. infra/

- `infra/docker-compose.yml` with these services:
  - `postgres` (postgres:16), `redis` (redis:7), `minio` (+ a one-shot `minio-init` that creates
    the private buckets `photos` and `evidence`), `livekit` (livekit/livekit-server, dev keys,
    `infra/livekit.yaml`).
  - `api`: Django under Daphne/ASGI (HTTP + `/ws/`), `worker`: Celery, `matcher`: placeholder
    loop process (real logic in M2), `admin`: Vite dev server.
  - Healthchecks on every service; `api` waits for postgres/redis.
- `infra/.env.example`; real `.env` git-ignored. Secrets only from the environment.

## 2. backend/

- Python 3.12 (in Docker), Django 5.2 LTS, DRF, Channels + channels-redis, Celery,
  SimpleJWT, drf-spectacular, django-environ, psycopg 3, boto3/django-storages, sentry-sdk.
  Dependencies pinned in `pyproject.toml`; `uv` for locking.
- Project `korram/` with split settings (`base`, `dev`, `test`); UUID primary keys and UTC by
  default.
- Apps created empty now, filled in later milestones: `accounts`, `matching`, `chat`, `safety`,
  `wallet`, `billing`, `core`.
  - `accounts.User`: the custom user model goes in now, because swapping `AUTH_USER_MODEL` later
    is painful. Fields from the PRD data model only (`phone`, `dob`, `gender`, `status`,
    `risk_score`, `created_at`).
  - `core/providers/`: empty interface modules (SMS, liveness, moderation, media, store
    receipts, Paystack), each with a `Fake` implementation, selected from settings.
- `GET /api/v1/health` checks DB and Redis → `{"status":"ok"}` 200 (503 if either is down).
- `/api/v1/schema/` (OpenAPI) and an empty authenticated `/ws/` consumer.
- Tooling: ruff (lint + format), pytest + pytest-django; tests for health OK and health 503.

## 3. app/ (Flutter 3.32, Dart 3.8)

- `flutter create` with org `com.korram`, Android + iOS only. minSdk 26 (Android 8), iOS 15.
- Packages: flutter_riverpod, go_router, dio. livekit_client is added in M3, when calls are
  built, to keep M0 small.
- **Design tokens** (`lib/theme/`): `KColors` (the 10 PRD colours plus the extra neutrals the
  canvas uses, such as `#26242F` surface-2, `#1A0E0B` on-coral ink and `#FF8D73` coral-hover),
  `KType` (Bricolage Grotesque 500/700/800 headings; DM Sans 400/500/700 body; sizes from the
  canvas: 40/34/24/17/16/15/14/13/12/11), `KRadius` (12/14/16/18/24), `KSpacing`. All
  exposed through `ThemeData` and a `ThemeExtension`. Widgets read tokens and never use
  literal colours.
- Fonts bundled as TTF assets (from the OFL sources on Google Fonts, licences included), not
  fetched at runtime, so first launch works offline.
- go_router with all 17 PRD routes registered; every route except `/welcome` shows a
  placeholder screen.
- **Welcome screen (01)** built to match `design/screens/01-Main.dc.html`: logo, 2×2 photo grid
  (placeholder tiles with the bracketed captions), headline, subcopy, the phone CTA, the
  Google and Apple buttons, and the 18+ legal line. The buttons go to their routes or do
  nothing until M1.
- Tooling: `flutter analyze` (flutter_lints, plus a lint against `Color(0x…)` outside
  `lib/theme/`), a widget test that Welcome renders its copy, and a golden test of Welcome at
  390×844.

## 4. admin/

- Vite + React + TypeScript; one page that calls `/api/v1/health` and shows the result.
  ESLint, plus Vitest with one test. The moderator console itself comes in M4.

## 5. CI (`.github/workflows/ci.yml`)

- Jobs: backend (ruff, pytest against service containers postgres + redis), app (`flutter
  analyze`, `flutter test`), admin (lint, test, build). The workflow is ready to run whenever a
  GitHub remote is added.

## 6. Top-level

- `README.md` (how to run), `.gitignore`, `Makefile` shortcuts (`make up`, `make test`).

## Out of scope for M0

Auth, OTP, any business logic, LiveKit tokens, real providers. Screens other than Welcome stay
placeholders.

## Decisions to confirm

- **Brand in UI copy:** the designs say "kora" (see questions.md #8). Welcome will use the
  design copy ("kora") until you decide.
- **Fonts bundled** rather than loaded with the `google_fonts` package. This works offline and
  helps the 40 MB size budget.
- **Django 5.2 LTS** with Python 3.12 in Docker. Your machine has Python 3.14, but containers
  keep everyone on the same version.

## Outcome (done)

- `make up` brings up all 8 services; `GET /api/v1/health` → 200 `{"status":"ok"}`; the
  app renders Welcome with bundled Bricolage Grotesque / DM Sans and the token colours
  (golden: `app/test/goldens/welcome.png`).
- Deviations from the plan:
  - Bucket creation runs as `manage.py ensure_buckets` on API start (the MinIO client image
    has no shell to script `mc`).
  - Host ports are offset (Postgres 5433, Redis 6380, API 8100, admin 5174) because this
    machine already runs Postgres, Redis and dev servers on the defaults.
  - Tokens are static `KColors`/`KType`/`KRadius`/`KSpacing` classes plus `ThemeData`; no
    `ThemeExtension` was needed yet. The "no literals" rule is enforced by a test
    (`test/theme_tokens_test.dart`) instead of a custom lint plugin.
  - Welcome shrinks its photo grid to fit (see questions.md #14).
